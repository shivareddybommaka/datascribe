# M8 demo — Billing + subscriptions

Account: `nova`. Repo root: `~/projects/datascribe`. Synthetic data only. No real card is charged:
without `STRIPE_SECRET_KEY` the Fake gateway is used, and Stripe only accepts test keys.

## Automated

```
pnpm --filter @datascribe/api test
```

```
pnpm --filter @datascribe/billing test
```

```
pnpm --filter @datascribe/web e2e
```

- API: `test/billing.test.ts` "M8 DoD: monthly invoice with overage, paid through the gateway". The
  monthly run issues plan fee + overage + GST with a sequential number. client_admin starts a checkout,
  and the signed webhook marks the invoice paid exactly once. Forged, unsigned and tampered webhooks are
  rejected. Finance refunds part, then the rest. Also: plans, subscriptions, usage, one-off invoices
  (gap-free numbers under concurrency), PDF, void, visibility, dunning, cancel at period end, catch-up.
- Billing package: money maths, invoice builder, dunning stages, gateways, PDF.
- E2E (needs `colima start` and `pnpm infra:up`): `e2e/finance.spec.ts` signs in as finance, issues
  a one-off invoice, downloads the PDF and voids it. It then adds 2,400 pages to Acme (Professional:
  2,000 included), runs monthly invoicing "as of" 40 days ahead and checks the invoice: US$1,499.00
  plan fee + 400 × US$0.75 = US$300.00 overage. Last, it creates a plan.

## By hand

```
colima start
```

```
pnpm infra:up
```

```
pnpm db:migrate
```

```
pnpm db:seed
```

```
pnpm dev
```

1. http://localhost:3000/console/finance: sign in as `finance@datascribe.example` with
   `SEED_USER_PASSWORD` from `.env` (first login asks you to set up an authenticator app).
2. Overview: MRR (US$1,998.00 for the two seeded firms), outstanding, overdue, and firms near their
   page limit.
3. Subscriptions: on Acme Injury Law, click **Add usage** and enter 2400. The meter turns red with
   "400 over".
4. Overview → Billing runs: set **As of (dev only)** to a date after Acme's period end (shown on
   Subscriptions), then click **Run monthly invoicing**. The status line counts the invoices issued.
   Click it again: nothing new is billed.
5. Invoices → open Acme's new subscription invoice: plan fee US$1,499.00, "Overage: 400 pages beyond
   2,000 included" US$300.00, GST line, total. Click **Download PDF**.
6. Invoices → **New one-off invoice**: pick a firm, add lines, issue. Then **Void** it (a reason is
   required).
7. Overview → **Run dunning** with an "as of" date after the due date. Reminders appear in Mailpit
   (http://localhost:8025) and the invoice shows as overdue.
8. Plans: create a plan, edit it, untick Active. Inactive plans stay listed but can't be chosen in
   **Change plan**.

Paying by card is done by the firm's client_admin from the portal billing screen, which is not built
yet. Until then the API test above covers checkout → webhook → paid → refund. To use real Stripe test
mode, set `STRIPE_SECRET_KEY=sk_test_…` and `STRIPE_WEBHOOK_SECRET` in `.env`, and forward webhooks to
`/api/v1/payments/webhook/stripe` with the Stripe CLI.
