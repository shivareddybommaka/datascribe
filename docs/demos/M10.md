## 1. Security fixes (part 1, D-100..D-110)

Automated:

```
pnpm --filter @datascribe/api exec vitest run --reporter=dot test/auth.test.ts test/logging.test.ts test/crm.test.ts test/supply-chain.test.ts
```

By hand (`pnpm dev`, web http://localhost:3010):

1. **Per-account limit (M6).** At the sign-in page, sign in 11 times as one unknown synthetic
   address (for example `nobody@example.com`): the 11th is refused with "Too many requests, try again later" (429,
   `RATE_LIMIT_ACCOUNT`), also from another browser.
2. **Single-use reset links (L2).** Forgot password twice for `client.user@acme.example`; in Mailpit
   open the first link: it is refused. The second works once, then is refused too.
3. **No values in error logs (L7).** Any Prisma error in the API log shows the name, code and model
   only, never the arguments (`test/logging.test.ts`).
4. **Contact form notice (L6).** `/contact` shows "Please don't include medical records, patient
   names or other health information…".
5. **Pinned supply chain (L12).** `docker-compose.yml` images by digest, workflow actions by commit
   SHA (`test/supply-chain.test.ts`). Database roles (L11): `docs/DB-ROLES.md`, not applied anywhere.

## 10. Retention / hard-delete job (part 6, D-128)

```
pnpm --filter @datascribe/api exec vitest run --reporter=dot test/retention.test.ts
```

```
pnpm --filter @datascribe/worker exec vitest run --reporter=dot src/retention.test.ts
```

By hand: as `super.admin@datascribe.example`, Admin → Organizations → Acme → retention 1 day. A case
needs `status = closed` and a `closedAt` older than that (M6 doesn't set `closedAt` yet, so the API
test builds that state). Run the worker with `RETENTION_DRY_RUN=true` to only count; without it the
file's S3 object and page text go, the portal shows "Deleted by retention", Download answers 410,
and Admin → Audit log lists one `document.retention_delete` per file.

## Known noise

The e2e run prints one or two `[WebServer] prisma:error document.findMany` lines before the first
test. Harmless (D-130): the worker's dispatcher polls while global setup drops and re-creates the
e2e schema, and its next tick succeeds.
