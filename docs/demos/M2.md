# M2 demo — Admin console

Account: `nova`. Repo root: `~/projects/datascribe`. Synthetic data only.

Definition of done (§12): a super admin creates a custom role and it takes effect without a restart.

## Automated

```
pnpm --filter @datascribe/api test
```

```
pnpm --filter @datascribe/web e2e
```

- API: `test/admin-console.test.ts` covers roles (the M2 DoD: create role → assign → the same access
  token gains access on the next request → remove the permission → access is gone), the "grant only
  what you hold" rule (audit M4), client-role rules, organizations, settings, email templates, the
  audit log viewer and CSV, read-only impersonation, and the concurrent-login lockout (audit M2).
  `test/admin-users.test.ts` covers the user actions.
- E2E (needs `colima start` and `pnpm infra:up`): `e2e/admin.spec.ts`. The super admin builds a role
  in the checkbox matrix, invites a new staff member with it (invite read from Mailpit), the new user
  signs in and is refused the audit log; the super admin ticks `audit_log view all` and the user's next
  page load shows it. Second test: "View as" a client admin shows the banner, writes are refused, Stop
  returns to the super admin, and both ends appear in the audit log.

## By hand

```
colima start
```

```
pnpm infra:up
```

```
pnpm db:migrate
```

```
pnpm db:seed
```

```
pnpm dev
```

1. http://localhost:3010/console/admin: sign in as `super.admin@datascribe.example` with
   `SEED_USER_PASSWORD` from `.env` (staff need an authenticator app the first time).
2. **Roles → New role**: name it "Audit reader", keep "Datascribe staff", tick `crm view all`,
   Create role.
3. **Users → Invite user**: Datascribe, a synthetic email, role "Audit reader". Open the invite from
   Mailpit (http://localhost:8025) in a private window and create the account, then sign in there.
   Open http://localhost:3010/console/admin/audit: "You do not have permission".
4. Back as super admin: Roles → Audit reader → tick `audit_log view all` → Save permissions. Reload the
   private window: the audit log loads. No restart.
5. **Users → Manage `client.admin@acme.example` → View as … (read-only)**: amber banner, only Acme's
   users; try Suspend on a user (refused, read-only). Stop viewing.
6. **Audit log**: filter "Action starts with" `admin.` and export CSV.
7. **Organizations → Edit** a client firm: plan, custom pricing, MFA policy, retention; Suspend signs
   its users out.
8. **Settings**: company and tax (used on invoice PDFs), SLA defaults, notification rules, email
   templates (try `{{patientName}}` in a template: refused), medical sources with 24-hour usage.
